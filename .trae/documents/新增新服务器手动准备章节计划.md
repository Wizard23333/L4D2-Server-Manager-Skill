### 3. 新章节的内容结构

章节会明确说明：这部分是“在后续所有自动化操作、Skill 指令、SSH 批量命令、L4D2 安装之前，需要你人工先完成的事情”，并强调不在公开文档中记录真实密码、私钥、token。

计划按以下顺序组织内容：

1. **确认服务器基础信息**
   - 记录公网 IP、系统版本、登录账号来源、是否有控制台/VNC/救援模式入口。
   - 说明这是后续配置 SSH 与防火墙的前提。
2. **完成首次登录**
   - 使用云厂商初始密码或已有密钥首次进入服务器。
   - 强调首次登录阶段不要立刻锁死自己，先确认还能回连。
3. **创建或确认可用的管理账号**
   - 明确推荐使用非 root 管理用户执行日常登录，再通过 `sudo` 提权。
   - 若云镜像已自带 sudo 用户，则改成“确认其可用并记录用户名”。
4. **配置 SSH 公钥登录**
   - 生成/确认本地公钥。
   - 把公钥加入服务器用户的 `authorized_keys`。
   - 验证新会话可免密登录。
5. **本地配置 SSH 别名**
   - 在本地 `~/.ssh/config` 写一个固定别名，例如 `myubuntu`。
   - 与仓库现有后续命令风格保持一致，避免全文里命令风格割裂。
6. **加固 SSH 登录策略**
   - 在“已确认公钥可用”之后，再考虑禁用 root 直登和密码登录。
   - 明确顺序要求，避免把自己锁在服务器外。
7. **配置云安全组与系统防火墙**
   - 先放行 `22/tcp`，确认 SSH 稳定。
   - 再根据当前阶段放行实际需要的端口，并区分：
     - `27015/udp`、`27016/udp` 等游戏端口；
     - `8080/tcp` 仅在启用 Web 面板时放行；
     - 云厂商安全组与服务器内 `ufw` 都要同步配置。
8. **执行基础系统校准**
   - 例如主机名、时区、系统更新。
   - 保持轻量，不扩展到软件安装教程。
9. **做一轮接入验证**
   - 从本地重新 SSH 登录。
   - 验证 `sudo`、`ufw status`、公网端口放行状态。
   - 确认此后才能继续执行 skill 里的安装与管理步骤。

### 4. 文案与风格要求

- 用中文撰写，和现有 `SKILL.md` 保持一致。
